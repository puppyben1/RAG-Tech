# 银行业监管可信 RAG 问答系统产品说明书

版本：V1.0  
适用项目：RAG-Tech 竞赛交付  
产品代号：RegRAG

## 1. 产品概述

RegRAG 面向银行监管制度、政策规章、统计报表和业务流程文件，提供可溯源、可核验、低幻觉的检索增强生成问答能力。系统帮助银行业务人员在信贷审批、风险分类、资本管理、消费者权益保护、反洗钱、支付结算、普惠金融和监管报送等场景中快速找到制度依据、指标口径和统计数据。

产品目标是实现：

- 问得准：识别事实查询、条款阈值、流程、表格取数和场景判断等意图。
- 找得到：从多源异构资料中召回最小充分证据。
- 答得清：准确表达规范强度、主体、日期、金额、比例和文号。
- 可追溯：答案关联来源页面、文件、页码、条款、工作表和单元格。
- 可复现：数据处理、索引、问答和评测均可按脚本重复执行。

## 2. 业务背景与痛点

| 业务现状 | 核心风险 | 系统应对 |
| --- | --- | --- |
| 资料分散于金融监管总局、人民银行、政府网等渠道 | 漏查、来源不权威 | 统一来源目录、哈希与官方 URL |
| Word、PDF、Excel 结构差异明显 | 条款层级和表头语义丢失 | 分格式解析并保留结构位置 |
| 文件更新频繁、版本关系复杂 | 误用旧规 | 版本状态、版本组与替代关系治理 |
| 关键词检索难以理解指标口径 | 同名指标混淆 | 混合检索、元数据过滤和表格结构检索 |
| 通用模型容易跳过依据直接回答 | 产生不可核验内容 | 证据门控、受控生成和依据不足拒答 |

## 3. 目标用户

| 用户角色 | 典型任务 | 主要需求 |
| --- | --- | --- |
| 银行业务人员 | 查询制度、核对流程、统计取数 | 快速、准确、易理解 |
| 合规与风险人员 | 判断适用条款和业务场景 | 权威来源、版本正确、完整引用 |
| 监管报送人员 | 查询指标定义、期间和单位 | 表格结构保真、数字零误差 |
| 知识库管理员 | 入库、审查来源和版本 | 可审计、可批量处理、问题可定位 |
| 评测与运维人员 | 运行评测、检查服务状态 | 指标可量化、环境可复现 |

## 4. 产品范围

### 4.1 本期范围

- Word、PDF、Excel 文档扫描、解析、结构化和索引。
- 文档、条款、段落、表格行和表格单元级证据检索。
- 关键词检索、向量检索、元数据过滤、混合重排。
- 制度事实、条款阈值、业务流程、统计取数和跨文件问答。
- 来源与版本可信控制、低置信度拒答。
- Web 工作台、CLI、HTTP API 和评测报告。

### 4.2 本期不承诺

- 未经授权的内部银行客户或交易数据接入。
- 对缺少权威来源和版本确认的资料作确定性监管结论。
- 用演示样例代替真实评测结果。
- 在未满足独立 holdout 治理要求时宣称达到最终比赛指标。

## 5. 量化目标

| 指标 | 目标值 | 验证方式 |
| --- | ---: | --- |
| 制度事实类准确率 | ≥ 85% | 独立制度事实评测集 |
| 表格取数类准确率 | ≥ 80% | 独立 Excel 评测集 |
| 证据引用命中率 | ≥ 90% | 标准证据定位对比 |
| 关键数字、日期、机构、文号错误率 | ≤ 5% | 关键实体逐项评分 |
| 资料外或依据不足拒答/澄清率 | ≥ 80% | 拒答专用评测集 |
| 支持入库文件数量 | ≥ 200 份 | 知识库构建报告 |
| 支持格式 | Word、PDF、Excel | 解析 smoke 测试 |
| 单轮响应时间 | 满足比赛平台要求 | P50/P95 延迟报告 |

## 6. 系统架构

```mermaid
flowchart LR
    A[官方页面与授权资料] --> B[来源目录与 Manifest]
    B --> C[Word / PDF 解析]
    B --> D[Excel 结构解析]
    C --> E[条款与段落单元]
    D --> F[表头 / 行 / 单元格事实]
    E --> G[BM25 与向量索引]
    F --> G

    H --> I[版本与权威性门控]
    I --> J[受控问答生成]
    J --> K[答案、证据与定位字段]
    K --> L[可信评测与新鲜度审计]
```

## 7. 数据设计

### 7.1 数据集组成

- 100 个 NFRA Word、PDF 和附件混合文件。
- 100 个 NFRA Excel 监管统计附件。
- 20 份重点监管文件目录。
- 42 条种子问答样本。

### 7.2 文档最小元数据

| 字段 | 说明 |
| --- | --- |
| `doc_id` | 稳定文档标识 |
| `title` | 文档标题 |
| `publisher` | 发文机关 |
| `doc_no` | 文号 |
| `publish_date` | 发布日期 |
| `source_type` | word、pdf、excel |
| `source_url` | 官方来源页面 |
| `attachment_url` | 官方附件地址 |
| `local_path` | 项目相对路径 |
| `sha256` | 文件完整性哈希 |
| `version_status` | current、superseded、unknown、not_applicable |
| `version_group` | 同一制度版本组 |

### 7.3 证据定位

- 文本证据：章节路径、条款编号、页码、结构单元 ID。
- 表格证据：工作表、行标题、列标题、单元格、单位、期间和原始值。
- 来源证据：来源 URL、附件 URL、版本状态和审核记录。

## 8. 核心功能

### 8.1 文档处理

1. 扫描原始资料并生成 Manifest。
2. 提取文档元数据、来源和版本信息。
3. 按标题、章节、条款和段落构造文本单元。
4. 展开合并单元格、多级表头和期间维度。
5. 生成文本、表格行和表格单元索引。
6. 导入 SQLite 并输出构建状态与错误报告。

### 8.2 混合检索

- 支持关键词 BM25 和本地向量召回。
- 支持按文件类型、文档、主题、版本、来源和日期过滤。
- 支持表格指标、期间、单位和表头结构匹配。
- 结果返回文档、位置、分数和原始证据文本。

### 8.3 可信问答

系统覆盖以下问答路由：

- 制度定义与事实查询。
- 适用范围和业务流程。
- 金额阈值、比例、日期和保存期限。
- 禁止性与义务性规定。
- Excel 精确取数和比较计算。
- 制度正文与统计报表跨文件判断。
- 资料不足、版本冲突和资料库外问题拒答。

### 8.4 可信控制

- `current` 和证据充分的 `not_applicable` 资料可形成权威回答。
- `superseded` 默认不进入当前有效结论。
- `unknown` 只能用于探索检索，不可形成确定性监管结论。
- 没有权威证据时必须拒答或明确降级，不生成占位来源。

## 9. 答案输出规范

```json
{
  "question": "用户问题",
  "answer_text": "基于证据形成的答案或拒答说明",
  "route": "rag_open | excel_lookup | excel_calc | rag_refusal",
  "confidence": "high | medium | low",
  "evidence": [
    {
      "doc_id": "文档标识",
      "source_title": "来源标题",
      "source_url": "官方地址",
      "version_status": "current",
      "position": {
        "page_no": 1,
        "article_no": "第三条",
        "sheet_name": null,
        "cell_ref": null
      },
      "text": "最小充分证据"
    }
  ]
}
```

答案表达要求：

- 保留“应当、可以、不得、原则上”等规范强度。
- 数字、单位、期间、机构名称和文号不得改写或估算。
- 推断内容必须与原文事实分开表述。
- 引用必须能回到原始文件和具体位置。

## 11. 页面与状态规范

所有异步功能必须提供四态：

- 空态：说明当前没有什么，并提供下一步操作。
- 载入态：显示正在执行的动作，避免误认为页面失效。
- 错误态：说明失败位置并允许重试。
- 成功态：显示结果、完成状态和后续入口。

视觉规范：

- 深色工具界面，背景 `#18181b`，主要卡片 `#242429`。
- 主强调色 `#1769ff`，只用于当前任务和关键动作。
- 成功、警告、错误使用独立语义色，不与主强调色竞争。
- 正文和控件满足 WCAG AA；键盘焦点使用 2px 可见描边。
- 高频操作仅保留 100–160ms 按压和颜色反馈，无阻塞入场动画。
- `prefers-reduced-motion` 下关闭位移和缩放反馈。

## 12. 评测与验收

评测集至少覆盖：

1. 监管制度事实题。
2. 条款和阈值题。
3. 业务流程题。
4. 统计表格取数题。
5. 跨文件场景判断题。
6. 资料不足与版本冲突拒答题。

验收报告必须记录代码提交、评测集指纹、知识库指纹、可信策略版本和生成时间。历史报告如与当前输入不一致，必须标为 stale，不能作为当前验收证据。

## 13. 安全与合规

- 仅使用公开官方资料和命题单位授权资料。
- 不接入客户个人信息、账户信息和交易明细。
- 不在日志中保存密钥或敏感问答输入。
- 本地路径以项目相对引用持久化，避免泄露机器目录。
- 来源、版本和审核信息不可用假数据补齐。

## 15. 答辩演示脚本

1. 在工作台展示入库文档、文本单元、表格事实和评测摘要。
2. 演示制度条款问题，展开来源、文号、章节和页码。
3. 演示 Excel 精确取数，展开工作表、行列标题、单元格和单位。
4. 演示比较计算，展示两个原始值与计算表达式。
5. 演示旧版冲突或资料不足问题，确认系统明确拒答。
6. 进入证据检索页，验证关键词、元数据过滤和混合重排结果。
7. 进入评测中心，说明指标、新鲜度和独立 holdout 验收原则。
