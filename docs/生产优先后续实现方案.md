# 生产优先后续实现方案

## 1. 总目标

本阶段目标从“比赛演示优先”调整为“生产能力优先”。系统后续建设顺序为：先补齐数据与索引底座，再增强检索模型和受控生成，最后补文档、演示包装和比赛材料。

当前策略是保留 JSONL 作为可复现中间产物，同时引入 SQLite 作为第一版生产数据底座。后续可平滑迁移到 PostgreSQL，并接入任务队列承载解析、补采、索引和评测任务。

## 2. 已确认设计决策

- 先做生产能力，再做文档和比赛包装。
- 第一阶段先增强数据与索引底座。
- 来源补采第一版采用 catalog 导入与自动合并校验，不直接做全自动爬虫。
- Excel 第一阶段增强 `table_rows`，补 `indicator / period / unit / headers / cells / source trace`。
- embedding 和 reranker 做成可插拔后端，保留 hashing/rule fallback。
- LLM 受控生成必须基于证据、输出 JSON schema、经过后校验，证据不足时拒答。
- 后端生产化采用“JSONL 复现 + SQLite 第一版 + 后续 PostgreSQL/任务队列”。
- 前端后续按“生产管理台 + 比赛演示入口”设计。

## 3. 总体路线

```text
P0 数据底座
  -> SQLite schema
  -> JSONL 导入
  -> 来源 URL catalog 合并
  -> 元数据覆盖率报告
  -> 表格语义字段增强

P1 检索增强
  -> embedding backend abstraction
  -> model embedding index
  -> reranker backend abstraction
  -> 检索评测对比

P2 受控生成
  -> LLM backend abstraction
  -> JSON schema answer
  -> citation/digit/refusal validation
  -> 问答日志和人工反馈

P3 生产管理
  -> 文档管理台
  -> 索引管理台
  -> 评测中心
  -> 增量任务队列

P4 比赛交付
  -> README/SPEC
  -> 演示脚本
  -> 评测报告
  -> 系统方案材料
```

## 4. 第一阶段实现内容

本轮先实现 SQLite 数据底座第一版：

```text
data/db/jinrong.sqlite3
src/jinrong/db/schema.py
src/jinrong/db/repository.py
src/jinrong/db/import_jsonl.py
```

第一版表结构：

- `documents`：文档主表，承载 manifest 和 document metadata 合并后的核心字段。
- `text_units`：Word/PDF 文本证据表。
- `table_rows`：Excel 行级证据表。
- `import_runs`：记录每次 JSONL 入库批次。
- `schema_meta`：记录数据库 schema 版本。

第一版 CLI：

```powershell
python -m jinrong.cli import-db --reset
python -m jinrong.cli db-status
python -m jinrong.cli validate-source-catalog --source-catalog data/intermediate/source_catalog_template.csv
python -m jinrong.cli import-source-catalog --source-catalog data/intermediate/source_catalog_template.csv --reset-catalog
python -m jinrong.cli metadata-audit
```

## 5. 后续开发顺序

1. 来源补采生产化：完善 `source_catalog` 校验、匹配分数、冲突报告和导入 UI。
2. 元数据增强：提升 `publisher / publish_date / doc_no` 覆盖率，并保留抽取依据。
3. 表格语义增强：从表格标题、sheet、行标题和列标题中抽取 `indicator / period / unit / headers`。
4. 模型检索：接入 `sentence_transformers` 或自定义 HTTP embedding 后端。
5. 模型重排：接入 reranker 后端，和规则重排做 A/B 评测。
6. LLM 受控生成：实现 schema 生成、引用校验、数字校验和拒答校验。
7. 生产前端：增加文档管理、来源补齐、索引管理、评测失败样例分析。

### 6.7 来源补采工作清单


排序策略：

### 6.8 现行版本优先与旧版抑制

已新增检索层版本策略，默认开启：

```text
prefer_current=true
include_superseded=true
```

策略含义：

- `current` 证据加分。
- `superseded` 证据降权。
- `include_superseded=false` 时直接过滤旧版证据。
- `unknown` 不调整分数，避免真实 catalog 未补齐时误删证据。

已接入：

```text
python -m jinrong.cli search ...
POST /search
fallback POST /search
```

接口返回中会包含：

```json
{
  "version_policy": {
    "prefer_current": true,
    "include_superseded": true,
    "method": "current_boost_superseded_penalty_v1"
  }
}
```

生产判断：这块属于比赛必需的“版本差异、旧规抑制、证据可信”能力底座。当前真实数据尚未标注 current/superseded，因此功能已实现但效果等待来源 catalog 补齐后释放。
