# 银行业监管可信 RAG 问答系统比赛交付总体方案

## 1. 项目定位与赛题目标

本项目面向银行业监管制度、政策规章、统计报表和业务流程文件，构建一个可溯源、可核验、低幻觉的检索增强生成问答系统。系统目标不是单纯做通用聊天，而是围绕监管和银行业务场景完成事实查询、条款依据检索、表格指标定位、统计口径解释、场景合规判断和证据追踪。

赛题重点能力包括：

- 多源异构资料解析：Word、PDF、Excel、CSV、JSONL 等。
- 条款与表格证据检索：支持制度正文、统计附件、行级表格证据。
- 可溯源问答生成：答案必须带证据、来源文件和位置。
- 幻觉抑制：资料不足时拒答。
- 复杂任务：支持合规判断、跨文件比较、制度口径加表格取数。
- 工程交付：提供后端服务、前端工作台、结构化知识库、评测报告和复现实验脚本。

## 4. 系统总体架构

系统按“离线构建 + 在线服务 + RAG 推理 + 前端评测”四层组织。

```text
原始数据 wendang/data
  -> 离线构建层
       manifest
       metadata
       text_units
       table_rows
       vector index
  -> 在线服务层
       FastAPI
       ask/search/documents/eval APIs
  -> RAG 推理层
       问题分类
       检索
       rerank
       证据充分性判断
       受控生成
       拒答
  -> 前端与评测层
       React 工作台
       可信评测中心
       评测报告
```

### 4.1 离线构建层

负责将原始文件转换为可检索、可追溯的知识库资产。

核心产物：

```text
data/processed/manifest.jsonl
data/processed/document_metadata.jsonl
data/processed/text_chunks.jsonl
data/processed/text_units.jsonl
data/processed/table_cells.jsonl
data/processed/table_rows.jsonl
data/index/text_vectors.jsonl
data/index/table_row_vectors.jsonl
```

### 4.2 在线服务层

负责提供统一 API。

核心接口：

```text
GET  /health
POST /ask
POST /search
GET  /documents
GET  /documents/{doc_id}
GET  /kb/status
POST /eval
GET  /eval/trusted/summary
GET  /eval/trusted/{case_type}
```

### 4.3 RAG 推理层

当前版本实现第一版受控 RAG 工作流。

核心流程：

```text
问题输入
  -> 问题类型识别
  -> 定向 query expansion
  -> BM25 / hybrid 检索
  -> 规则 rerank
  -> 证据充分性判断
  -> 受控模板生成或拒答
  -> 返回答案和证据链
```

当前支持的 route：

```text
rag_open
rag_refusal
compliance_judgement
text_then_table
multi_hop
excel_lookup / excel_calc / excel_compare
text_mcq / excel_mcq
```

### 4.4 前端与评测层

React 前端提供：

- 工作台：展示知识库整体状态。
- 问答：支持 QA ID 和自定义问题。
- 证据检索：展示检索证据和元数据。
- 文档库：浏览 500 份入库文件。
- 知识库状态：查看处理统计。
- 评测中心：展示传统 QA 评测和可信评测 summary。

## 5. 数据清洗与知识库构建方案

数据清洗主线为：

```text
wendang/data 原始文件
  -> manifest.jsonl
  -> document_metadata.jsonl
  -> text_chunks.jsonl
  -> text_units.jsonl
  -> table_cells.jsonl
  -> table_rows.jsonl
  -> text_vectors.jsonl / table_row_vectors.jsonl
  -> retrieval_eval / trusted_eval
```

### 5.1 manifest 管理

每个本地文件在 manifest 中记录：

- `doc_id`
- `title`
- `file_name`
- `local_path`
- `file_ext`
- `file_size`
- `sha256`
- `source_type`
- `period`
- `source_url`
- `attachment_url`
- `column`

当前真实来源 URL 尚未完全补齐，但已经具备字段、模板导出和合并流程：

```powershell
python -m jinrong.cli export-source-template
python -m jinrong.cli enrich-manifest --source-catalog data/source_catalog.jsonl
```

### 5.2 Word/PDF 文本解析

Word/PDF 被转换为两级文本资产：

- `text_chunks`：基础文本块。
- `text_units`：带章节、页码、条款位置的结构化文本单元。

主要用于：

- 制度事实问答。
- 条款依据检索。
- 合规判断。
- 证据链追踪。

当前边界：

- `.doc` 当前仍可能存在解析质量不如 `.docx` 的情况。
- 复杂 PDF 双栏、扫描件、公式、复杂表格仍需 MinerU、OCR 或专业 parser 增强。

### 5.3 Excel 表格解析

Excel 被转换为：

- `table_cells`：单元格级事实。
- `table_rows`：行级 RAG 证据。

表格问答优先使用 `table_rows`，因为它更适合保留指标行、期间列、单位和多个值之间的关系。

当前支持：

- 按文件标题、期间、指标名称召回。
- 返回工作表、行号、行标题、单元格引用、单位和值。
- 支持商业银行监管指标表、保险公司经营情况表等典型统计附件。

当前边界：

- 对复杂多层表头、跨 sheet 计算、同比环比计算仍需增强。
- 第一版多跳比较主要返回证据级比较框架，尚未做完整数值差异计算。

## 6. RAG 检索与可信生成方案

当前版本定位为第一版受控 RAG，而不是完全通用的智能推理系统。

### 6.1 检索策略

当前包括：

- BM25 检索。
- local hashing embedding 检索。
- BM25 + vector hybrid 检索。
- 规则 reranker。
- 元数据过滤。
- doc_id 定向检索。
- 针对特定问题类型的 query expansion。

### 6.2 问题类型识别

系统按问题类型进入不同路径：

| 类型 | route | 说明 |
| --- | --- | --- |
| 开放事实问答 | `rag_open` | 检索证据后模板化回答。 |
| 资料不足 | `rag_refusal` | 虚构主体、未来年份、证据不足时拒答。 |
| 表格取数 | `rag_open` + `table_row` | 优先返回行级表格证据。 |
| 合规判断 | `compliance_judgement` | 输出判断、依据、风险点、缺失事实。 |
| 制度口径 + 表格证据 | `text_then_table` | 先检索文本口径，再检索表格证据。 |
| 跨文件比较 | `multi_hop` | 为每个对象分别检索证据并生成比较框架。 |

### 6.3 证据充分性与拒答

拒答策略包括：

- 资料外问题前置拒答。
- 虚构主体识别。
- 未来年份识别。
- 敏感个人信息类问题识别。
- 证据覆盖率判断。
- 具体实体缺失检查。
- 数字一致性检查。

拒答输出固定为：

```text
无法根据当前资料确定。
```

### 6.4 受控生成

当前默认使用模板化受控生成。

可选 LLM 受控生成已具备接口，但不是当前评测通过的必要条件。后续接入 LLM 时，应继续保持：

- 只依据证据回答。
- 输出结构化 JSON。
- 检查答案数字是否来自证据。
- 检查答案是否脱离证据。
- 证据不足时拒答。

## 9. 当前边界与风险

当前版本边界：

- 来源 URL 和附件 URL 字段已具备，但真实 URL 尚未完全补采。
- PDF/Word 复杂版式解析仍需专业工具增强。
- `.doc` 解析质量可能弱于 `.docx`。
- 当前 embedding 是本地 hashing 版本，不等同于真正语义模型。
- reranker 是规则版本，不等同于模型级 cross-encoder reranker。
- 多跳比较第一版主要返回证据框架，尚未完成所有数值差异自动计算。
- 50 条 trusted_eval 已全部通过，但仍需扩充 dev/holdout 评测集。
- 前端当前展示报告，但还没有从前端触发可信评测任务队列。
