# 银行业监管可信 RAG 竞赛展示规划

## 1. 展示目标

比赛展示不能停留在“可以聊天”。评委需要在有限时间内确认以下五件事：

1. 系统能够正确解析 Word、PDF、Excel 多源异构资料。
2. 系统能够找到具体条款、指标和最小充分证据。
3. 系统能够完成表格取数、跨文件检索和多跳推理。
4. 系统不会把旧规、未知来源或资料外内容包装成确定答案。
5. 系统的准确率、证据命中、拒答和延迟可以独立复现和验证。

展示主线应统一为：

> 一份真实监管资料如何进入知识库，一道真实业务问题如何找到证据，答案如何被验证，系统如何证明自己没有编造。

## 3. 必须具备的展示功能

### P0-1 五条黄金演示链路

首页必须提供五个固定、可重复、带金标的演示入口。

| 演示题型 | 评委看到什么 | 系统必须做到什么 | 验收标准 |
| --- | --- | --- | --- |
| 制度事实题 | 回答、官方来源、页码/章节 | 从当前有效制度中返回直接事实 | 答案与金标一致，证据文档命中 |
| 条款/阈值题 | 金额、比例、期限、适用对象、例外 | 保留规范强度和所有限定条件 | 关键实体零错误，条款定位命中 |
| 业务流程题 | 按步骤组织的流程和责任主体 | 合并同一制度内多个相关条款 | 步骤完整，无无依据扩展 |
| Excel 取数题 | 工作表、行列标题、单元格、单位、期间 | 精确定位并返回原始值 | 数字、单位、期间完全一致 |
| 跨文件/拒答题 | 制度口径与表格数据联合证据，或明确拒答 | 完成多跳推理；版本冲突或证据不足时拒答 | 引用覆盖全部推理节点，拒答不带伪证据 |

做到什么才算完成：

- 每条演示链路固定输入、预期路由、标准答案和标准证据。
- 实时模式调用真实 API，演示模式必须明确标注为预置数据。
- 每条链路可在 30–45 秒内完成，并能展开证据详情。
- 演示前运行 smoke，确保所有入口当场可用。

### P0-2 可验证证据链

问答页右侧证据区需要统一展示：

- 来源标题、发文机关、文号。
- 官方来源 URL 和附件 URL。
- 版本状态、有效日期、替代关系。
- PDF/Word 页码、章节和条款编号。
- Excel 工作表、行标题、列标题、单元格、单位和期间。
- 检索方式、基础分、重排分。
- 用于回答的原始证据片段。

做到什么才算完成：

- 点击一条证据可以回到本地原始文件或官方来源。
- 当前有效、历史旧版、未知版本使用清晰且不只依赖颜色的标签。
- 答案中的每个关键数字和结论都能对应至少一条证据。
- 没有来源的字段显示“未验证”，不能显示占位 URL。

### P0-3 来源与版本可信中心

文档中心需要增加可信状态过滤和覆盖率摘要：

- 已验证官方来源数量与覆盖率。
- 当前有效、已废止、未知、统计快照数量。
- 缺失来源 URL、发布日期、文号和版本关系的工作清单。
- 来源证明方式、审核人、审核时间和证据。

做到什么才算完成：

- 评委能看到系统如何防止误用旧规。
- 未完成治理的资料不会被包装成权威回答。
- 展示页面明确区分“全库入库数量”和“已完成可信治理数量”。

### P0-4 赛题指标看板

评测中心不能只展示一个总准确率，应直接对应赛题五项指标：

1. 制度事实准确率。
2. 表格取数准确率。
3. 证据引用命中率。
4. 关键实体错误率。
5. 资料外/依据不足拒答率。

同时展示：

- P50、P95 和最大响应时间。
- 评测集版本、SHA-256 和案例数量。
- 代码提交、知识库指纹、可信策略版本和生成时间。
- current/stale 状态及 stale 原因。
- 每类失败样本和失败原因分布。

做到什么才算完成：

- 指标来自独立冻结、外部复核的 holdout，不使用开发集自证。
- 报告与当前代码、数据不一致时自动标为 stale。
- 比赛平台延迟阈值确认后，延迟门禁自动判断通过或失败。

### P0-5 知识库构建与解析质量

需要一个只读的“构建状态”页面或工作台区域，展示：

- 文件总数及 Word、PDF、Excel 分布。
- 成功、失败、需要人工复核的文件数。
- 文本单元、带条款号单元、带页码单元数量。
- 表格、表格行、单元格和多级表头解析数量。
- 重复文件、哈希冲突和路径审计结果。
- `.doc` 专项抽检和解析质量状态。

做到什么才算完成：

- 展示数据来自当前构建报告，不写死在前端。
- 每个失败项可以定位到文件和错误阶段。
- 评委可以从总览下钻到一个真实文档的结构化结果。

### P0-6 一键复现与系统健康

工作台应提供明确的交付健康状态：

- 后端、数据库、索引和前端构建状态。
- 当前 Git 提交和依赖锁文件状态。
- 最近一次隔离重建时间与结果。
- 一键复制启动、验证和重建命令。

做到什么才算完成：

- 在新 Windows 目录中可以按说明完成安装、构建和 smoke。
- 路径审计不出现机器相关绝对路径。
- 所有核心测试和前端生产构建通过。

## 4. 建议补强功能

### P1-1 检索调试台

用于证明系统不是“模型直接回答”：

- 同时显示 BM25、向量召回、RRF 合并和重排结果。
- 支持文件名、主题、业务领域、条款、期间和版本过滤。
- 显示召回结果变化和未命中原因。
- 为黄金演示题保存可重复的检索快照。

### P1-2 跨文件推理轨迹

对跨文件问题展示简洁的证据图：

```text
问题
  → 制度文件：确认指标定义与口径
  → 统计附件：定位期间与单元格
  → 计算步骤：使用原始值完成比较
  → 答案：结论 + 全部引用
```

轨迹只展示真实执行步骤和证据，不展示模型内部思维过程。

### P1-3 答案质量保护

- 关键数字、日期、机构和文号的答案后校验。
- 规范强度词与原文一致性检查。
- 引用覆盖检查：结论没有证据时阻止输出。
- 同名文件、版本冲突和期间歧义时要求澄清。

### P1-4 数据合规审计

- 展示敏感信息扫描结果和人工处置状态。
- 证明数据只来自公开官方资料或授权资料。
- 日志不保存 API Key、个人信息或完整敏感输入。

## 5. 页面优先级

| 页面 | 本轮必须展示 | 后续增强 |
| --- | --- | --- |
| 工作台 | 五条黄金链路、知识库规模、可信覆盖、评测状态 | 最近运行与告警 |
| 可信问答 | 问题、执行状态、答案、证据抽屉 | 多会话、反馈闭环 |
| 证据检索 | 混合检索、过滤、最小证据 | 多路召回 A/B 调试 |
| 文档中心 | 文档详情、来源、版本、结构位置 | 来源治理工作流 |
| 构建状态 | 格式分布、解析覆盖、失败项 | 单文档解析预览 |
| 评测中心 | 五项指标、延迟、指纹、新鲜度 | 趋势和版本对比 |
| 方案说明 | 背景、架构、数据、交付和验收 | 答辩材料导出 |

## 6. 七分钟答辩演示流程

| 时间 | 演示内容 | 要证明什么 |
| --- | --- | --- |
| 0:00–0:40 | 工作台总览 | 500 份异构资料、系统状态、可信覆盖和评测状态 |
| 0:40–1:30 | 制度事实/条款题 | 能准确找条款，保留文号、主体和规范强度 |
| 1:30–2:20 | Excel 精确取数 | 能理解多级表头、期间、单位和单元格 |
| 2:20–3:20 | 跨文件问题 | 能从制度口径跳转到统计报表并完成计算 |
| 3:20–4:10 | 旧版冲突或资料外问题 | 能识别不可信证据并拒答，不产生幻觉 |
| 4:10–5:00 | 文档与版本中心 | 能回到官方来源，解释版本治理和证据位置 |
| 5:00–6:10 | 评测中心 | 五项指标、独立 holdout、延迟和报告新鲜度 |
| 6:10–7:00 | 复现与总结 | 测试、构建脚本、环境指纹和交付清单 |

## 7. 演示前硬门槛

以下项目未通过时，不应进行正式答辩演示：

- 五条黄金演示题均完成独立金标和证据复核。
- 正向题只使用已验证来源和有效版本。
- 独立 holdout 已冻结，五类题每类至少五题，并有外部审核记录。
- 五项赛题指标和延迟报告来自当前代码与当前知识库。
- 关键路径 smoke、完整 pytest 和前端构建通过。
- Windows 隔离重建通过，路径审计为零问题。
- `.doc` 人工抽检与敏感信息审计完成。

## 8. 当前最优实施顺序

1. 将首页演示链路从三条补齐为五条，并为每条建立独立金标。
2. 在证据卡中补齐来源 URL、版本状态和可点击原文定位。
3. 在工作台和文档中心展示可信治理覆盖率，优先扩大官方来源验证范围。
4. 完成外部复核的独立 holdout，并让评测中心读取最终验收报告。
5. 增加构建状态页和解析质量下钻，证明多源异构解析能力。
6. 确认比赛延迟阈值，补齐性能门禁和真实运行数据。
7. 最后再评估真实 embedding/reranker 替换，不让模型升级抢占可信治理工作。

## 9. 展示设计评审

| 现状 | 改为 | 为什么 |
| --- | --- | --- |
| 首页只有三条演示题 | 首页固定五条赛题覆盖链路 | 与赛题建议的五类问题直接对应 |
| 工作台主要展示入库规模 | 同时展示入库规模与可信治理覆盖率 | 防止把“已入库”误解为“可权威回答” |
| 评测页偏通用准确率 | 直接展示赛题五项指标、延迟和新鲜度 | 让评委可以按命题指标验收 |
| 文档详情以文件字段为主 | 增加官方来源、版本状态和审核证明 | 证明系统能够避免旧规和伪来源 |
| 跨文件能力只体现在答案中 | 增加真实证据节点和计算轨迹 | 让多跳推理过程可验证 |
| 运行说明主要在文档中 | 工作台提供健康状态和可复制命令 | 现场故障时能快速定位并恢复 |
