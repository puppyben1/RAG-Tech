# CR-20260807 Windows 原生参赛版交付设计

状态：W0-W3、W5-W6 工程实现完成；W4 类别存在性完成但样本量、金标和外部复核待办，gate blocked；S2 最终验收待办  
关联需求：COMP-001、COMP-003、COMP-004、COMP-005、COMP-006、COMP-007、COMP-008

## 1. 背景与问题

目标环境是 Windows 10/11，不能依赖 WSL、Docker 或 Ubuntu。当前工程已经具备监管文本、统计表格、证据返回、拒答、合规判断和多跳问答主链路，因此不迁移到 WeKnora、PrivateGPT 或其他完整 RAG 应用。

2026-08-07 的本机诊断结果为：Python 3.12.6 环境可建立，25 个自动化测试通过，500 份文档的现有知识库可读取，前端生产构建通过。当前检入的历史产物仍包含旧机器绝对路径；路径审计报告 524 个唯一引用问题，其中 514 个为旧绝对路径、10 个为无效项目引用。该结果只能作为诊断证据，不能作为比赛验收结果。

## 2. 目标

在 Windows 原生环境交付一个可以从原始资料重建、启动、演示和评测的可信 RAG 参赛版，并以独立评测证明赛题指标。

必须保持以下既有能力：

- `doc_id`、SHA-256、来源和版本元数据；
- `text_units`、`table_rows`、`table_cells` 数据契约；
- 条款/段落/表格单元级证据；
- Excel 确定性取数和计算；
- 资料不足拒答、旧版过滤和关键实体校验；
- FastAPI、React 和命令行入口。

## 3. 非目标

- 不整体迁移到 WeKnora、RAGFlow、PrivateGPT、AnythingLLM 或 Kotaemon；
- 不要求 Docker、WSL、Linux 服务端向量库或 GPU；
- 不在独立 holdout 冻结前更换默认检索算法；
- 不通过批量字符串替换修复历史 JSON/JSONL 路径；
- 不把当前 50/50、60/60 或 300/300 历史结果作为最终比赛指标。

## 4. 交付切片

### S0：Windows 可复现基线

实现内容：

1. 使用 `scripts/bootstrap.ps1` 从干净目录创建 `.venv` 并锁定 Python 依赖；
2. 从 `wendang/data` 在仓库外的隔离副本中重建全部知识库产物；
3. 运行编译、测试、路径审计、前端构建和 API smoke；
4. 生成带 Git SHA、数据集指纹、锁文件指纹和逐项检查结果的基线报告；
5. 明确区分“诊断运行”和“干净工作区批准运行”。

API smoke 在本阶段只验证服务和契约可运行：`/health`、`/kb/status`、`/documents`、`/search` 返回成功，资料不足问题正确拒答。需要权威来源的正向事实回答属于 S1 验收，不能通过降低可信门禁来让 S0 通过。

验收：500/500 文档处理成功、构建错误为 0、自动化测试和前端构建通过、路径审计问题为 0，原始 `wendang/` 不发生修改。

### S1：来源与版本可信治理

实现内容：

1. 按现有 source worklist 分批补充官方来源页、附件 URL、发布日期、文号和栏目；
2. 来源候选必须经过候选、可重复验证、批准、导入四步；机器可验证证据可以替代人工签字，无法自动证明的部分才进入人工复核；
3. 为制度文件标记 `current`、`superseded`、`unknown`，统计快照标记 `not_applicable` 并保留期间；
4. 对来源缺失或版本未知的高风险监管答案执行拒答或显式降级提示。

首批处理现有 `source_catalog_batch_01_candidate.jsonl` 中的 4 份候选文档：`nfra_397`、`nfra_398`、`nfra_390`、`nfra_389`。候选数据必须完成官方页面、附件、适用状态和生效时间的来源证明；程序可以执行只读自动核验，但不得自行把 `current` 结论写成已确认，也不得伪造审批人。无法自动证明的部分才进入人工复核。

验收：演示使用的重点文档来源和版本覆盖率为 100%；全库覆盖率单独报告，不虚构缺失字段。`TRUST_TEXT_001` 等权威正向样例返回 `rag_open`，虚构机构等负例继续返回 `rag_refusal`。

### S2：独立比赛评测

实现内容：

1. 冻结互不重叠的 `dev` 和 `holdout`；
2. holdout 由非实现人员复核，不允许由当前检索结果自动生成标准答案；
3. 覆盖制度事实、条款/阈值、业务流程、统计取数、跨文件场景判断和不可回答负例；
4. 输出逐题结果、失败原因、端到端延迟和以下赛题指标。

评测报告必须包含 Git SHA、评测集指纹、知识库核心产物指纹、可信策略版本和生成时间。读取报告时，只要任一指纹与当前运行不一致，就标记为 `stale`，前端和 API 不得把它展示为当前通过结果。

验收阈值：制度事实准确率不低于 85%，表格取数准确率不低于 80%，证据引用命中率不低于 90%，关键数字/日期/机构/文号错误率不高于 5%，拒答/澄清率不低于 80%。

### S3：检索质量增强

前置条件：S0 通过且 S2 holdout 已冻结。

候选顺序：

1. 保留现有 BM25；
2. 在 Windows CPU 上对小型中文 embedding/reranker 做冒烟测试；
3. 使用 BM25 和语义召回的独立候选集，经 RRF 融合后再做重排；
4. 新后端必须输出现有 evidence 结构，并继续经过来源、版本、拒答和数字一致性门禁；
5. 只有 holdout 指标提升且 P95 延迟可接受时，才修改默认配置。

首选候选为 BGE/BCEmbedding；Docling 仅用于 PDF/DOCX A/B 解析。现有 `.xls/.xlsx` 单元格解析器不得被 Docling 替换。

### S4：答辩演示闭环

固定五条演示链路：制度事实、条款阈值、Excel 取数、制度加表格的跨文件问题、资料不足或旧版冲突拒答。

每条答案必须同时显示：答案、证据原文、文件标题、来源链接、版本状态，以及页码/条款或 `sheet!cell` 位置。演示页面不得依赖联网模型才能完成基础回答。

## 5. 兼容与迁移

- 现有 API 请求和 evidence 响应保持向后兼容；
- 当前 `retrieval=bm25|hybrid` 和 `rerank` 参数继续有效；
- 新解析器、embedding、reranker 只能作为可选实现接入，不改变 JSONL 契约；
- 历史产物只读保留，正式产物必须从原始输入重新生成；
- 不引入向量数据库，除非规模或性能报告证明 JSON 索引成为瓶颈。

## 6. 风险与回滚

- 新模型在 CPU 上延迟过高：回滚到 BM25、哈希向量和规则重排；
- Docling 解析降低条款或页码质量：保留 legacy 解析结果并按文件回退；
- 来源或版本无法核实：标记未知并阻止权威结论，不猜测；
- holdout 指标下降：恢复冻结基线，不针对单题继续堆规则；
- 全量重建失败：只在隔离副本中排错，不覆盖当前历史产物。

## 7. 实施顺序

严格按 `S0 -> S1 -> S2 -> S3 -> S4` 推进。S0、S1、S2 是可参赛和可信性的基础；S3 是质量加分项；S4 将工程证据转化为答辩可见成果。任何阶段未通过验收，不进入依赖它的下一阶段。
